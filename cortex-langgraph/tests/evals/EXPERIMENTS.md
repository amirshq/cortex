# RAG experiments: results summary (roadmap step 4.1)

These are the RAG pipeline experiments, one row each. The full numbers for every run are
in [`results/RESULTS.md`](results/RESULTS.md), generated by `compare_runs.py`. The raw
data is in `results/<label>.json`.

**How every experiment was run**
- **Change one component and keep everything else fixed.** Settings that belong to the
  component change with it (for example, the overlap follows the chunk size, and each
  re-ranker gets its own threshold).
- **Build on the winners.** Each experiment starts from the winners of the ones before it,
  upstream components first.
- **Hold the measurement fixed.**
  - The same 30-question golden set from *AI Engineering*: 24 answerable, 6 unanswerable.
  - The same judge: `gpt-4o`, calibrated before every run.
  - From 3.1 on, the answer LLM runs at temperature 0, so a difference comes from the
    change, not chance.
  - Every experiment has a control run made under the same conditions.
- **Trust large gaps only.** With 30 questions, one question is about 4 points. Only
  differences of 2 or more questions, or ones with a clear cause, count as wins.

## Final run (step 4.3): all winners together

`results/final.json` is the plain `config.yml` (no CLI overrides) run against the **app's
index**, not an experiment index. It's the reference that the tools in `tests/tools/` (RAGAS,
DeepEval thresholds) are checked against.

| Metric | `llm-gpt-4.1` (experiment) | **`final`** (app) |
|---|---|---|
| Index coverage | 0.958 | 0.958 |
| recall@1 / @5 / @10 · MRR | 0.75 / 0.875 / 0.875 · 0.793 | 0.75 / 0.875 / 0.875 · 0.793 |
| Context recall (any / all) | 0.875 / 0.833 | 0.875 / 0.833 |
| Accuracy · refusal | 0.833 · 1.0 | 0.833 · 1.0 |
| Grounded answers · claims supported | 0.957 · 0.977 | 0.913 · 0.953 |
| Relevance | 0.957 | 0.957 |
| Latency mean / p95 | 1.10 s / 1.73 s | 1.12 s / 1.50 s |
| $ / 1,000 questions | $2.00 | $2.00 |

- **The winners combine as expected.** Retrieval is identical, so the re-indexed app store
  matches the experiment index. Nothing interacts badly.
- **Groundedness differs by one answer (q19), and that's noise.** At temperature 0, gpt-4.1 is
  still not fully deterministic: this time its q19 answer added an unsupported comparison
  (vector DB vs API spending). 4 of 30 answers changed wording between the two runs. Regression
  thresholds (4.4) need a margin of at least one question for this reason.
- **The final run was made twice** (the second time to save the chunk texts, below). Same
  configuration, so the differences show the run-to-run noise that 4.4's thresholds must allow
  for:
  - **retrieval, accuracy, refusal and groundedness: identical** (grounded 0.913, q19 and q27
    ungrounded both times);
  - **relevance: 1.0 → 0.957** (q28 rated partial once);
  - **5 of 30 answers worded differently** (q10, q11, q16, q19, q30);
  - **latency: 1.53 s → 1.12 s**, which is OpenAI API variance, not any setting.
- **Each question's chunks are saved** in `final.json` → `results[].contexts`: the 5 chunks the
  LLM saw, in prompt order, with their text, id, position and vector score. RAGAS
  (`tests/tools/ragas/`) scores the run from this file without re-running it.
- Remaining misses are the known ones: q02 (footnote not indexed), q20 (Docling table misparse,
  correct refusal), q27/q28 (paraphrases).

## What's still open
- **Ingestion:**
  - q02's footnote is still not in the index;
  - Docling misparses one table, behind q20.
- **Paraphrase questions:** still 2/4. Hybrid (BM25 + vector) search is untested.
- **More questions:** the results need confirming on a larger golden set (100–200 questions)
  and on several PDFs. Re-rankers in particular usually matter more when there are many
  documents.
- **Phase 4.4:** regression tests (DeepEval, in `tests/tools/deepeval/`), with thresholds from
  the final run minus a margin.
